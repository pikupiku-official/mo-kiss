# 夜のコルクボードシステム要件

合意日: 2026-10-21  
状態: 付箋表示・操作、夜の導線、発言記録とセーブ対応を実装済み（2026-10-21）。

追加要件反映: 付箋の文字を枠内に収まる範囲で拡大し、ホバーはハイライトのみ、クリックで会話欄を開く方式へ変更。

## 目的

通常の会話で集めたタネを、夜の家で付箋として自動記録する。人物と話題ごとに整理された固定配置のボードを見ながら、根拠となった発言を振り返れるようにする。

日記はその日の振り返りを担い、コルクボードは過去も含めたタネの蓄積・確認を担う。

## 取得と記録

- 取得条件は既存仕様を引き継ぐ。対象のタネが登場した会話を通り、イベントを正常完了すると取得が確定する。
- ハイライトのクリックや補足会話の閲覧は、取得条件にしない。
- タネ1つにつき付箋1枚とする。
- 同じタネを別の会話で取得するケースは、制作側で設けない。
- 付箋本文は、制作側があらかじめ用意した短い要約とする。ゲームはその要約を自動で記録・表示する。
- 取得したタネの根拠として、ハイライトを含む発言全体と、その実際の話者を対応付ける。
- プレイヤーが実際に通った会話だけを振り返れるようにする。未閲覧の補足会話や未選択の分岐を表示しない。
- 過去の付箋も保持し、セーブ・ロード後に取得済みの付箋を再現する。

## タブとカテゴリ

| タブ | 表示対象 |
|---|---|
| すべて | 拾ったタネすべて |
| 桃子 | 桃子に関するタネ |
| 沙那子 | 沙那子に関するタネ |
| その他 | 上記以外に関するタネ |

- タネは「桃子」「沙那子」「その他」の人物区分のいずれか1つに所属する。「すべて」はそれらをまとめて表示するためのタブとする。
- 人物区分とは別に、「両親について」「妹について」「近況について」などの話題カテゴリを持つ。
- タネ1つが所属する話題カテゴリは1つとする。
- 人物区分と話題カテゴリは制作側が指定する。
- タブは話している人物ではなく、タネが関する人物で分ける。クリックで開く会話欄には実際に発言した話者を表示する。

## 固定配置と色

- 制作側がタネごとの配置をあらかじめ指定し、同じ話題カテゴリの付箋がまとまるようにする。
- 取得順や取得数による再整列、ソートは行わない。
- 未取得の付箋は表示せず、取得後に所定の位置へ表示する。
- 第一ターニングポイント前後の区分を、制作側がタネごとに設定する。

| タネに設定する区分 | 付箋の色 |
|---|---|
| 第一ターニングポイント以前 | 淡い黄色 |
| 第一ターニングポイント以後 | 淡い青 |

- 第一ターニングポイントの区切りは人物ごとに独立する。
- 「その他」のタネも制作側が前後のどちらかに指定する。
- 色はタネの設定で固定し、実際の取得時期では変えない。ターニングポイント通過後も、それ以前の付箋を塗り替えない。
- 色は前後の区別に使い、話題カテゴリの区別には使わない。

## 夜の導線と演出

1. 家で日記によるその日の振り返りを行う。
2. コルクボードへ移り、新規付箋が見える範囲で自動的に貼っていく演出を行う。
3. 貼り付け演出の完了後は、そのまま自由に閲覧できる。
4. 「戻る」で家の自由行動へ戻る。

- 自動貼り付けの演出はスキップ可能にする。
- スキップすると、新規付箋がすべて配置された状態で自由閲覧に移る。記録対象を減らしたり、未配置のまま残したりしない。
- 家の自由行動にある「コルクボードを見る」から、自主的に再確認できる。
- 通常の再閲覧で付箋の重複登録や貼り直しを行わない。

## 閲覧操作

- 4つのタブを切り替えて表示対象を変更できる。
- ボード内を拡大・縮小、画面移動できる。
- 付箋にカーソルを合わせると、その付箋をハイライトする。ホバーだけでは会話欄を開かない。
- 付箋をクリックすると、画面下の既存ダイアログ欄に対応する話者とセリフを表示する。
- 会話欄は常駐させず、閉じている間はボードを下まで広く表示する。
- 表示対象はハイライト部分だけでなく、そのハイライトを含む発言全体とする。

## 実装した操作・表示の詳細

- タブ4つは常時表示する。カテゴリ見出しは、そのカテゴリの付箋が表示されている場合だけ描画する。
- 「すべて」と人物別タブは共通の固定座標を使い、人物別タブでは対象だけを表示して表示範囲を合わせる。タブ切り替え時は全体表示に戻す。
- 付箋の基本サイズは350×240。色は以前がRGB `(255, 242, 169)`、以後が `(187, 222, 246)`。
- 付箋本文は要約の長さに合わせて、本文領域に収まる最大のフォントサイズを選ぶ（上限96）。句読点だけが最終行に残るサイズは避ける。極端に長い要約も描画領域内へ縮小する。カテゴリ見出しのフォントサイズは36。
- ホイールでカーソル位置を基準に拡大・縮小する。倍率は25～180%。画面上の「−」「＋」でも変更できる。
- 背景の左ドラッグ、またはボード内の中ボタンドラッグで移動する。付箋自体の座標は変えない。
- 「全体表示」ボタン、Homeキー、0キーで、そのタブの付箋を見渡す表示に戻す。
- 貼り付け演出は700msごとに1枚を表示し、新しい付箋へ順に画面を合わせる。最後の付箋も表示時間を確保してから、新規付箋全体を見渡す表示にする。
- 演出中の左クリック、Enter、Space、Ctrlで演出を一括完了する。同じ入力で「戻る」などを同時に実行しない。
- その夜の新規付箋には、自動表示中と続く閲覧中に `NEW` を付ける。家から開き直した通常閲覧では付けない。
- クリックした発言を会話欄に保持する。別の付箋へのホバーでは本文を切り替えず、その付箋をクリックすると切り替える。
- 会話欄の「閉じる」、ボード背景の左クリック、タブ切り替えで会話欄を閉じる。閉じた後はボードが再び下まで広がる。
- 会話欄を開く際は、クリックした付箋が欄の裏に隠れないよう必要な分だけ画面を移動する。固定座標や倍率は変えない。
- 長い発言は既存の会話欄と同じ文字組みで3行ずつに分ける。左右キー、PageUp/PageDown、または下欄の左側・右側クリックで前後のページを読める。
- 「戻る」ボタンかBackspaceで家へ戻る。Escは既存の設定画面を開く。
- 新規付箋0件の夜は、日記の後に家の自由行動へ進む。任意のボード閲覧は可能。

## 制作側の設定

設定先は `data/seed_catalog.json`。既存の6件には開始用の仮カテゴリ・座標を設定した。既存6件はすべて第一TP以前のタネなので黄色とし、沙那子タブは対応するタネを追加するまで空になる。

ルートの `board_categories` にカテゴリを登録する。

```json
{
  "id": "MOMOKO_FAMILY",
  "group": "momoko",
  "title": "両親について",
  "position": [80, 80]
}
```

- `id`: カテゴリの固有ID。
- `group`: `momoko`、`sanako`、`other` のいずれか。これが人物別タブの所属になる。
- `title`: カテゴリ見出し。
- `position`: ボード全体での見出しの固定座標 `[x, y]`。

各タネに `corkboard` を指定する。付箋の本文は既存の `journal_text` を使う。

```json
"corkboard": {
  "category_id": "MOMOKO_FAMILY",
  "phase": "before_tp1",
  "position": [0, 0]
}
```

- `category_id`: 所属先のカテゴリIDを1つ指定。
- `phase`: `before_tp1` が淡い黄色、`after_tp1` が淡い青。タネの取得日やプレイヤーの現在の進行からは計算しない。
- `position`: カテゴリの左端・見出し下からの相対座標。最終座標は `[カテゴリx + 付箋x, カテゴリy + 58 + 付箋y]`。
- 隣の付箋は横に380、次の段は縦に280程度離すと、基本サイズで重ならない。
- 存在しないカテゴリ、不正な人物区分・前後区分・座標、同一カテゴリ内の座標重複はロード時にエラーにする。

既存カタログで `corkboard` が省略されている場合は、人物IDと既存の日記ページ・枠から暫定の固定位置を作る。正式な配置には上記の明示設定を使う。

## 発言記録と旧セーブ

- 実際に表示したタネ付き発言を、変数置換後の話者・本文・女性色指定とともにイベント中の一時記録へ保存する。
- イベント正常完了時に、その発言を `seed_state.json` の取得記録の `source_dialogue` へ確定する。
- イベント途中のセーブにも、通過済みタネと発言を `pending_seeds` として含める。ロード時に未選択の分岐を再生して補完しない。
- ボード閲覧では会話の描画機能だけを再利用し、タネ取得・イベント進行・バックログ追加を再実行しない。
- この変更より前に取得したタネには元の発言が保存されていない。付箋と要約は表示し、下欄には元の発言が記録されていない旨を表示する。未閲覧の会話から推測して埋めない。

## 確認方法

既存のチュートリアル6件を別の一時プロフィールで取得して表示するプレビューを用意した。通常の進行データは変更しない。

```powershell
.\.venv-gd\Scripts\python.exe tools/preview_corkboard.py --sample
```

`--animate` で貼り付け演出を確認できる。`--sample` を付けない場合は、現在の保存済みタネを読み取り専用で表示する。

プレビューはPygameのウィンドウを開く。Qtのウィンドウ初期化を省く設定はスクリプト内で行うため、起動前にQtの環境変数を手動設定する必要はない。

画像の書き出し例:

```powershell
.\.venv-gd\Scripts\python.exe tools/preview_corkboard.py --sample --snapshot outputs/corkboard-review/all.png
```

関連回帰テスト88件が通過。実際の `HOME_DIARY.ks` からボード・家へ戻る入力経路、途中セーブ復元、旧セーブ、2色・タブ・座標・演出スキップ・変換後ホバーを確認した。追加要件のホバーとクリックの分離、会話欄の開閉、下部の付箋のクリック、大きくした文字の描画範囲も確認する。1440×1080画像と960×720の縮小画像で配置・文字・2色・会話欄の見え方を目視確認済み。QtのWindowsプラグインに依存しない起動の回帰テストと、SDLのWindowsドライバによる実ウィンドウの起動・画像書き出しも確認した。

## 受け入れ条件

1. イベントを正常完了して取得したタネだけが対象になり、未選択分岐や未閲覧の補足会話は表示されない。
2. 夜に新しいタネの要約が1枚ずつの付箋として登録され、過去の付箋も残る。
3. 貼り付け演出を途中でスキップしても、完了時と同じ付箋が同じ位置にそろい、そのまま閲覧できる。
4. 自主的な再閲覧やセーブ・ロードでも、付箋が消えたり重複したりしない。
5. 4つのタブが定義どおりに対象を切り替え、タネの人物区分と話者が異なる場合も正しく表示する。
6. タネの取得順が異なっても、配置と色が制作側の指定どおりになる。
7. ホバーはハイライトのみとし、クリックした付箋の実際の話者と発言全体を画面下で読める。会話欄を閉じるとボード全体へ戻る。
8. 拡大・縮小・移動後も、描画位置とホバー判定が一致する。
9. 「戻る」で家の自由行動へ戻れる。

## 既存設計との関係

既存の `タネシステム設計.md` 第10章にある人物別の恒久的な整理・確認の役割は、このコルクボードが担う。画面のタブ構成とカテゴリ配置には本書の要件を適用する。

既存設計にある人物別ロジックツリー、親子線、ターニングポイント別ページは、今回の合意には追加していない。タネの親条件など既存の取得・進行制御は維持する。
