# event_editor stepシーンエディタ変更仕様

> 初版: 2026-08-21  
> 対象: `event_editor.py` の「step編集」  
> 状態: Phase 1〜4の基本操作を実装済み。Undo/Redo、タイムライン、確認アニメーションは未実装

## 1. 目的

従来のstepプレビューは、KSを実行した最終画面を1枚のPNGへ平坦化して表示する。
新しいstepシーンエディタでは、背景・キャラクターなどを個別のGUIオブジェクトとして
ステージ上へ描画し、選択、右クリック、ドラッグ、プロパティ編集を可能にする。

KS形式とゲームランタイムは維持し、エディタ内の構造化モデルを保存時に既存タグへ戻す。

## 2. シーン状態

各stepは次の3状態を明示的に区別する。

1. `before`: 直前stepまでを実行した状態
2. `actions`: 現在stepに記述されたアクション列
3. `after`: 現在stepのアクションを実行し終えた状態

前stepから引き継いだキャラクターを操作しても、過去のタグは変更しない。
現在stepへ差分アクションを追加する。

| 対象 | ステージ操作 | KSへの反映 |
|---|---|---|
| 現在stepの `chara_show` | ドラッグ | 同じ `chara_show` の `x/y` を更新 |
| 引き継ぎキャラ | ドラッグ | 現在stepへ `chara_move` を追加または更新 |
| キャラのパーツ変更 | Shift | `chara_shift` を追加または更新 |
| キャラの非表示 | Hide | `chara_hide` を追加 |
| 新規キャラ | Show | `chara_show` を追加 |

直接ドラッグの既定動作はMoveとする。`chara_shift` の位置パラメータを編集する場合は、
アクション列で対象のShiftを明示的に選択する。

ドラッグの具体的な書き戻し規則：

- 現在stepのShowが最終的な絶対位置を決めている場合、そのShowの`x/y`を更新する。
- 現在stepのMoveが最終的な位置を決めている場合、そのMoveの`left/top`へ差分を加算する。
- 位置指定ShiftがShowや既存Moveを上書きしている場合、Shiftの後ろへMoveを追加する。
- 引き継ぎキャラに現在stepのMoveがない場合、新しいMoveを追加する。
- 追加するMoveの`zoom`は現在表示中の値を引き継ぎ、意図しない`1.0`へのリセットを防ぐ。
- 繰り返しドラッグでは、使用可能な既存Moveを更新し、タグを増殖させない。

## 3. 画面構成

```
┌──────── オブジェクト一覧 ───────┬──────── ステージ ─────────┬──── プロパティ ────┐
│ 背景: room01                   │                           │ name / x / y       │
│ キャラ: MMK  引き継ぎ          │      選択枠付きキャラ       │ size / fade / time  │
│ キャラ: SZK  このstepで表示     │      ドラッグ操作           │ キャラパーツ        │
│ SE: door01                     │                           │ volume / block      │
└───────────────────────────────┴───────────────────────────┴───────────────────┘
┌──────────── 現在stepのアクション列 ─────────────────────────────────────────┐
│ [show SZK] [move MMK 600ms] [se door01] [hide SZK]                         │
└─────────────────────────────────────────────────────────────────────────────┘
```

当面は既存のアクション一覧・プロパティ編集欄を利用し、ステージ選択と同期する。
ステージ描画とPygame最終確認画像はタブで併存させる。

- step編集ウィンドウはプレビュー側を主領域とし、初期幅のおよそ3分の2を割り当てる。
- プレビュー内ではステージを大きく、セリフ欄を下部の補助領域として配置する。
- 最終確認画像は元Pixmapを保持し、タブ表示・リサイズごとに現在の枠内へ4:3維持で再縮小する。

### 3.1 ステージ操作

- 左ドラッグ: キャラ移動
- `Shift + 左ドラッグ`: 最初に移動量が大きくなったX/Y軸へ固定して移動
- `Shift + マウスホイール`: ポインター下、または選択中のキャラを拡大縮小
- キャラ上で右クリック: Move / Shift / Hide
- キャラ以外で右クリック: ステージ追加メニュー

背景は通常ステージ全面を覆うため、右クリックのヒット判定対象にはしない。
キャラに当たらない右クリックは背景画像上でもステージメニューを開き、背景操作は
明示的な「背景」サブメニューから選択する。

ステージメニューから追加できる項目：

- `chara_show`
- `bg_show` / `bg_move` / 現在の背景アクション選択
- `bgm` / `se` / `bgmstop` / `bgmstart`
- `choice` / `fadeout` / `fadein`
- `flag_set` / `if` / `endif` / `event_control`

## 4. 実行前から実行後への確認アニメーション

### 4.1 表示仕様

- 保存・適用前に `before -> transition -> after` をループ再生できる。
- 既定表示サイズは640x480以下とする。
- 1秒以下の遷移は最大12fps、最大12フレームを目安とする。
- `time` が長い場合も確認用再生時間へ圧縮し、無制限にフレームを増やさない。
- Show、Shift、Move、Hide、背景Move、Fadeを対象とする。
- 音声は波形や再生中アイコンで示し、GIF画像そのものには音を含めない。

### 4.2 負荷対策

表示だけなら毎回GIFファイルへエンコードせず、常駐Pygameワーカーが生成したフレームを
Qtのタイマーで切り替える「GIF相当のインメモリアニメーション」を既定とする。
実ファイルのGIF出力は任意のエクスポート機能とする。

- キー入力ごとの生成は禁止し、300ms以上のデバウンスを行う。
- KS内容、step番号、アクション内容のハッシュでフレームをキャッシュする。
- 新しい要求が来た場合、未開始の古い要求を破棄する。
- 通常編集は即時のGUIオブジェクト描画を使い、Pygameフレームは最終確認に限定する。
- ドラッグとホイールはPygameスナップショットを自動生成せず、`Preview Update`で最終確認する。
- ホイールの連続入力は120msで束ね、最後の倍率だけをKSアクションへ反映する。

この制限なら常時GIFエンコードする方式より軽く、既存の常駐スナップショットワーカーを
拡張して実装できる。

## 5. 前後step移動

- step編集画面上部に「前のstep」「次のstep」を常設する。
- 現在位置を `step N / total` で表示する。
- 端では該当ボタンを無効化する。
- 移動時は現在の編集内容をエディタバッファへ適用してから隣のstepを開く。
- KSファイル一覧から別ファイルへ移る場合も、未保存なら保存・破棄・キャンセルを確認する。
- 保存に失敗した場合は現在ファイルに留まり、選択表示も元へ戻す。
- キャンセルは現在の編集を破棄し、step移動もしない。
- 将来は `Ctrl+PageUp` / `Ctrl+PageDown` も同じ動作へ割り当てる。
- 選択中オブジェクトとプレビュータブは、同名オブジェクトが存在する限り維持する。

## 6. chara_show / chara_shift パーツテンプレート

### 6.1 保存内容

テンプレートはキャラクター単位で保存し、次のフィールドを持つ。

```json
{
  "id": "generated-id",
  "name": "笑顔・制服",
  "character": "桃子",
  "parts": {
    "torso": "MMK_T00_ARM01_CLO00",
    "brow": "MMK_F00_BRO00_00",
    "eye": "MMK_F00_EYE00_00",
    "mouth": "MMK_F00_MOU04_01",
    "cheek": "MMK_F00_CHE00_00",
    "effect": "",
    "accessory": ""
  },
  "blink": true
}
```

- `x/y/size/fade/time` は既定では保存しない。立ち位置テンプレートとの混同を避ける。
- 必要になった場合は、別種の「配置テンプレート」として追加する。
- 選択中キャラクターと異なるキャラクターのテンプレートは候補に表示しない。
- 呼び出し時は、選択中キャラクターと互換性のない古いパーツを除去する。

### 6.2 操作

- `chara_show` / `chara_shift` のパーツ編集画面に「テンプレート保存」「呼び出し」を追加する。
- Shiftへの適用では、既定で現在状態との差分パーツだけをタグへ書き込む。
- テンプレート名の変更、複製、削除を可能にする。
- 保存先はリポジトリ内のエディタ専用JSONとし、ゲームのセーブデータとは分離する。

## 9. 追加済みの編集操作

- 選択中の立ち絵は四隅のハンドルをドラッグして等比拡大縮小できる。
- 拡大縮小は `chara_show.size`、`chara_shift.size`、または
  `chara_move.zoom` へ既存の直接編集規則で書き戻す。
- 立ち絵パーツ選択ウィンドウには、編集中stepの未保存の話者名とセリフを表示する。
- `fadeout` / `fadein` / `bgm` / `se` だけで構成するstepは、
  「セリフなしの単独step」指定により入力待ちを持つ独立stepにできる。
- 単独stepの境界は `;@standalone-step` で保存し、空行には境界の意味を持たせない。
- 対話プレビューは開始stepを指定できる。開始前のstepは状態構築だけ行い、
  指定stepのアクションから通常再生する。
- step編集画面上部の「このstepからプレビュー」は、編集中の内容をエディタへ
  適用して現在のstep番号を開始位置へ設定し、既存の保存確認付きプレビューを起動する。
